# Known Issues and Limitations

- Pokémon Y now boots on the Galaxy S25 Ultra to its logo/intro after the user selected and confirmed German (about 59.8 FPS / 100% in the observed session). A process restart before the game reached save setup returned to language selection, so the language choice has not been proven persistent. Gameplay compatibility, audio, save persistence, broader controls, and stability remain unverified.
- Physical hardware app startup, JNI/Android setup, Pokémon Y title boot, rendering, and D-pad navigation are verified. Audio, save handling, broader controls, and stability are not yet verified.
- The Azahar loader recognizes 3DSX homebrew, but PokeDaisy's current game entry path accepts only decrypted supported retail NCSD carts. No homebrew test harness or content is currently wired through the app.
- Production/device builds package Azahar for `arm64-v8a`. An opt-in `-Ppokedaisy.n3dsX86_64=true` build now runs 3DS games on the x86_64 API 36 AVD for runtime checks; this is an emulator-only build path, not the default Dev/release ABI set. The old translation AVD still crashed with SIGILL.
- `SCREEN > 3DS CORE` is present but currently has one usable backend (Azahar), plus `AUTO` as an alias. The Windows v1.6.2-beta.1 reference adds DS HUD/zoom behavior on Windows; it does not supply another 3DS core. Azahar Libretro is excluded from the Android build, and there is no general Android Libretro host in this app yet.
- Full app unit suite passes: 4,207 tests, 0 failures, 60 skips across 191 classes. ROM-dependent skips and the Windows symlink limitation are documented in `TEST_RESULTS.md`.
- Azahar's native binary makes the optional APK large. Review size/performance before release.
- Some historical notes in `docs/3DS_GAMES_PLAN.md` describe earlier device-validation status; they are dated and remain as historical context. Current device evidence is summarized in `PROJECT_STATUS.md` and `TEST_RESULTS.md`.
- Ultra Moon reached its first player-profile photo question in German on the Galaxy S25 Ultra at about 30 game FPS / 100% speed. Ultra Sun is recognized by tests but has not had a device boot check. Neither Ultra title has a verified companion RAM map; companion polling is intentionally disabled until title-specific addresses are verified. Ultra Moon's current session has not reached an in-game save or been restarted after the language selection.
- `ONE SCREEN` closed/open/closed behavior is visually verified on the x86_64 API 36 emulator with Pokémon Y at its language prompt: top-only while closed, actual 4:3 touch surface while open. Ultra Moon also boots on this build to its language prompt. API 36's explicit `SurfaceView` composition order fixes the leak that parent/view alpha alone did not. The S25 runs Android 17 / API 37, but this follow-up did not update or visually check it; hide behavior below API 36 remains unverified.
- Ultra Sun has identity and launch routing, but no Ultra Sun ROM is available for a runtime check and its existing-save metadata format remains unmapped. Do not synthesize metadata for an unrecognized Ultra Sun save until live evidence is available; a clean game can still create its own save.
- Importing private preferences from the installed official package is blocked: it is a non-debuggable app with `allowBackup=false`. Dev's own preferences are preserved by `adb install -r`; Android does not permit reading the official package's private SharedPreferences on this unrooted device.
- The current Pokémon Y x86_64 run confirmed the user-authorized German choice and stopped at `Begin game` / `Select language`, before any personal setup. Persistence across a process restart is unverified. This was emulator evidence, not an S25 Ultra run. The Android ARM64 AVD cannot start on this x86_64 Windows host.

- A startup wait on an invisible touch `TextureView` was resolved: the latest x86_64 build starts Ultra Moon with only the top surface and adds the second native window when TOUCH SCREEN is opened. Closed/open/closed visuals are verified on emulator-5558. The S25 Ultra was updated in place but not visually checked.
- Ultra Sun / Ultra Moon have no verified gameplay memory map. The EU Ultra Moon `LangSelect` module is now recognized from its observed root (`0x008b2000`) and opens both screens automatically; all other USUM modules remain `UNMAPPED`. The Companion's live HUD/party/map/battle data and gameplay-driven lower-screen behavior remain unavailable. Manual TOUCH SCREEN is the fallback outside that startup screen. Do not copy Sun/Moon RAM addresses into Ultra games without live validation.
- On mapped 3DS games, the dimmed-area dismiss action now sends B for auto-opened field menus and battle bag/party pages. The policy is unit-tested, but the S25 battle-page interaction remains unverified because USUM battle state is currently unmapped.
- The headless `n3ds_dump` build needs C++20 explicitly on its executable target. The initial local Docker build had overlapping CMake/Ninja writers; task-created containers were stopped. Rebuild and run one instance at a time before using it for ROM-backed memory analysis.

# Ultra Sun / Ultra Moon mapping remains open (2026-11-22)

Ultra Moon EU was booted in the isolated headless Azahar harness and its initial `LangSelect` CRO root was observed at
`0x008b2000`. This does not establish save-backed field, party, bag, battle, or touch-scene addresses. The USA Sun/Moon
map at `0x00869000` must not be assigned to USUM without runtime evidence. The production companion now reports the
unmapped status, but full USUM Companion and automatic lower-screen behavior are still unsupported.

- The current x86_64 emulator run advanced Ultra Moon in German to Kukui's photo/profile setup view and stopped before any photo/profile choice. Runtime modules are `AppDemo`, `SequencePlayer`, and `Object`; these remain unmapped, so Companion data and scene-driven lower-screen behavior are still unavailable. Intro performance was about 17–18 game FPS / 33–36 system FPS and is not S25 evidence.

- **Ultra Moon static RomFS:** the EU cart's German tables, Gen 7 moves/personal data, zones, wild encounters, icons, and island maps are now verified through a ROM-gated unit test. USUM uses its own text indices and `a/2/3/8` map SARC. This does not enable live Companion telemetry or automatic lower-screen behavior; those still require a verified USUM memory map.
