# Azahar Android build: license evidence audit

Source audit of the Azahar revision bundled by the optional Android 3DS build. This note records build and notice
evidence; it does not approve redistribution of the combined APK.

## Scope and build graph

The checked-out Azahar source is pinned at `219d743a1e698101fe1ab8bef43e6563126c3c27` (`2126.2`). The app builds
Azahar as a CMake subdirectory and links `citra_core`, `citra_common`, `audio_core`, `video_core`, and `input_common`
into `libpk_n3ds.so` (`n3ds/src/main/cpp/CMakeLists.txt`). It enables cubeb, OpenGL and Vulkan and disables Azahar's
Qt, SDL, tests, room frontends, web service, scripting, GDB stub, OpenAL, libusb, Discord RPC and libretro frontends.
Azahar's Android application target is not built.

The selected source targets still link these components:

- `citra_core` links Boost, `httplib`, dds-ktx, Crypto++, fmt, lodepng and `open_source_archives`
  (`third_party/azahar/src/core/CMakeLists.txt:507-509`). `core.cpp` and `perf_stats.cpp` are in that target's source
  list; `core.cpp` carries a GPLv3-or-later header, while Azahar's root `license.txt` is the GPLv2 text.
- `audio_core` links FAAD2, SoundTouch, Teakra and cubeb (`src/audio_core/CMakeLists.txt:47-56`).
- `citra_common` compiles MicroProfile and links fmt, bundled library headers, Boost, Crypto++, zstd and xxHash
  (`src/common/CMakeLists.txt:61-63, 157-178`).
- `video_core` links GLAD for OpenGL and VMA, Sirit, SPIR-V, glslang, Vulkan headers, dds-ktx, nihstro and robin-map
  for Vulkan (`src/video_core/CMakeLists.txt:156, 205-225`).

The build definitions are direct evidence of configured inclusion. This audit did not rebuild or inspect a packaged APK,
and does not infer whether the linker removes any unused objects.

## Specific attribution and notice gaps

### cpp-httplib

`src/core/CMakeLists.txt:508` links the bundled header-only `httplib` target. The tree contains active uses, including
`src/core/hle/service/http/http_c.cpp`, and the bundled header is `externals/httplib/httplib.h` version 0.14.0. Its
header identifies Copyright (c) 2023 Yuji Hirose and the MIT License; `externals/httplib/README.md` points to upstream
commit `0a629d739127dcc5d828474a5aedae1f234687d3` and says MIT. There is no separate license file in that directory.
Azahar's Android `src/android/app/src/main/res/values/licenses.xml` records the component name, description, link and
copyright but no full MIT license text. PokeDaisy's `app/build.gradle.kts` `azaharParts` and `NOTICE` do not list
cpp-httplib. The optional PokeDaisy license asset therefore needs this component's notice and full license text before
the APK can be treated as notice-complete.

### GLAD and Khronos headers

The bundled `externals/glad/src/glad.c` and `include/glad/glad.h` say they were generated by GLAD 0.1.36; its README
records the GL/GLES APIs and generation command. Azahar's Android license catalog records the GLAD name, project URL
and David Herberth copyright, but no license grant or text. The official GLAD v0.1.36 README says generated code may
be public domain, WTFPL or CC0, and cautions that Khronos specification-source licenses may apply. The exact
redistribution terms for this generated output are not established by the pinned tree. Separately,
`externals/glad/include/KHR/khrplatform.h` carries a Khronos copyright and permission notice; that notice is also
missing from PokeDaisy's optional license asset.

Primary references: `third_party/azahar/externals/glad/Readme.md`, `src/glad.c`,
`include/KHR/khrplatform.h`, and Azahar's Android `licenses.xml`; see the [GLAD v0.1.36 upstream README](https://github.com/Dav1dde/glad/blob/v0.1.36/README.md)
and [LICENSE](https://github.com/Dav1dde/glad/blob/v0.1.36/LICENSE).

### Generated system archive data

`externals/open_source_archives/Readme.md` says the checked-in arrays were generated by
`B3n30/citra_system_archives` at `0baa5f5773432f04e3e671859780ded965c4248c`. That repository describes itself as a
generator of custom system archives because the original 3DS archives are copyrighted; its repository is marked
GPL-2.0. The generated headers include `shared_font.app.romfs.h`, `mii.app.romfs.h`,
`country_list.app.romfs.h` and `bad_word_list.app.romfs.h`. `src/core/file_sys/archive_ncch.cpp:177-202` embeds and
serves these arrays as replacements, and `open_source_archives` is linked into `citra_core`.

The pinned Azahar tree does not state a separate license or authorship for the generated binary data, and the
`open_source_archives` directory has no separate license file. The generator's GPL label alone does not establish the
output's rights, and this audit does not assume the bytes are Nintendo originals or that they are independently
redistributable. The generator's README says it creates custom archives because the original 3DS archives are
copyrighted. Confirm the provenance and terms for each checked-in generated asset, or remove them from the Android
build, before release. The primary upstream reference is the [generator repository at the exact cited commit](https://github.com/B3n30/citra_system_archives/tree/0baa5f5773432f04e3e671859780ded965c4248c).

### GPL notices and FAAD2

The Azahar root `license.txt` is the GPL version 2 text. Compiled `src/core/core.cpp` is explicitly GPLv3-or-later;
additional files carry GPLv3-or-later headers. FAAD2's `externals/faad2/faad2/COPYING` prohibits non-GPL use without a
separate license and its GPL text offers version 2 or any later version. That is more precise than saying only “GPL v2”:
the file itself permits a later GPL version. This observation does not resolve how the root Azahar license, the
mixed-version files, FAAD2, PokeDaisy's GPLv3 terms and the final linked work interact. A license review must classify
the exact files and confirm the distribution/source-offer obligations for the final binary.

### PokeDaisy's Azahar patch

`NOTICE` currently describes `third_party/patches/azahar-pokedaisy.patch` as build-only. The checked-in patch also
changes runtime code: it adds an optional memory-write watch hook in `src/core/memory.cpp`, removes a shared cache from
`GetPhysMemRegionInfo`, and guards invalid software-renderer texture reads in
`src/video_core/renderer_software/sw_rasterizer.cpp`. The notice should describe these runtime changes accurately and
identify their license/attribution basis. The affected source files retain their upstream headers, while the patch
adds PokeDaisy comments; this audit does not determine the licensing of the combined modifications.

## Release gates

Before describing the Android 3DS package as redistributable or notice-complete:

1. Add the missing cpp-httplib attribution and full MIT text to `NOTICE` and the optional in-app license asset.
2. Resolve GLAD's generated-code terms for this exact specification output and include both GLAD attribution and the
   separate Khronos header notice in the in-app license asset.
3. Establish the origin and redistribution terms for each generated system archive array, or exclude them.
4. Review the mixed GPL headers, FAAD2's version choice, the PokeDaisy patch and the source/binary compliance package
   together. Do not infer compatibility from the root `license.txt` alone.

This audit performed no Gradle build, binary patching, device test or legal determination.
